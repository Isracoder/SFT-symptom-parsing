# Finetuning a small LLM to parse menstrual health logs 🩸📋

_From messy period-tracking notes to strict, schema-valid JSON_

A small language model (Qwen 3 1.7B) fine-tuned (kaggle, unsloth) to turn free-form menstrual health logs that users could write in an app or transcribe via speech-to-text (e.g "ugh cramps are killing me, slept 5-6h, no spotting today though") into a closed 14-field JSON object. This is the kind of structured extraction a menstrual health application could use to power symptom trends, cycle insights, and check-ins.
This type of functionality aims to reduce friction and increase user engagement through providing a more natural UX.

Built as a fun learning project to answer a specific question honestly: **how much does fine-tuning actually buy you over prompting, and does grammar-constrained decoding close the gap?**

## 🎯 Project Overview

- **Task:** extract a fixed JSON object (cycle day, flow, spotting, symptoms + severity, denials, painkiller, supplements, sleep, energy, mood, hair, skin) from noisy user logs.
- **Model:** Qwen3-1.7B, fine-tuned with QLoRA (Unsloth) on Kaggle.
- **Data:** 250 train / 35 validation / 60 gold, generated from immutable **fact cards**. The training and validation data were generated by LLMs, and validated on metrics such as symptoms distribution and similarity by other sub-agents (More on the cons later).
- **Held-out test:** gold uses **three sentence structures the model never saw in training**, all handwritten by me, to measure generalisation rather than memorisation.
- **Evaluation:** a 2×2 comparison — base vs fine-tuned × free vs grammar-constrained decoding — scored with macro field-level F1 and JSON parse rate.

---

## 🛠️ Technologies Used

- **Model:** Qwen3-1.7B (safetensors, not GGUF) with `enable_thinking=False`
- **Training:** Unsloth QLoRA (r=16, alpha=32, dropout 0, lr 1e-4, 3 epochs), plain `transformers.Trainer`, loss masked to completion tokens only
- **Constrained decoding:** lm-format-enforcer with a JSON Schema version of the 14-key contract
- **Infra:** Kaggle GPU notebooks, 4-bit quantisation, PEFT adapter saved separately from the base model
- **Data tooling:** deterministic Python generators and audit scripts, stdlib only

## 📊 Results

Evaluated on the frozen 60-record handwritten gold set. Identical prompt and greedy decoding in every cell.

| Model          | Decoding        | Macro field F1 | JSON parse rate |
| -------------- | --------------- | -------------: | --------------: |
| Base           | Free            |          0.557 |             35% |
| Base           | Constrained     |          0.503 |            100% |
| **Fine-tuned** | **Free**        |      **0.818** |        **100%** |
| **Fine-tuned** | **Constrained** |      **0.831** |        **100%** |

An interesting (though perhaps expected) result is _where_ the fine-tuned model still fails which is not finding symptoms, but grading them:

| Model      | Decoding    | Symptom detection F1 (name only) | Severity agreement |
| ---------- | ----------- | -------------------------------: | -----------------: |
| Base       | Free        |                            0.220 |                31% |
| Base       | Constrained |                            0.365 |                33% |
| Fine-tuned | Free        |                            0.746 |                30% |
| Fine-tuned | Constrained |                            0.784 |                35% |

**Takeaways**

- **Fine-tuning is the main win:** +26 F1 points and parse rate 35% → 100%.
- **Constrained decoding fixes form, not content.** On the base model it _lowered_ F1 while pushing parse rate to 100% — forced to emit complete JSON, it invented symptoms (169 false positives).
- **On the fine-tuned model, constraints add only ~1.3 points**, so the adapter alone is enough for deployment. They do eliminate real errors, though: free decoding emitted `"severity": "medium"` (not in the accepted vocabulary), constrained decoding produced the correct `"moderate"`.
- **Severity calibration is the weakest link.** The model collapses uncertain cases to `moderate` or drops the band to `null`; gold uses the full `mild`/`severe` range. This is due to my human handwritten examples naturally differing from the AI generated ones making it probably hard to generalize the severity calibration.

## 🧠 Core Project Decisions

- **Fact cards before text.** Every example started as a structured card; the LLM only wrote the log text. Labels are therefore exact by construction, not re-annotated.
- **Closed schema and vocabularies.** 14 keys in fixed order, `null` = not mentioned, `[]` = empty list. `null` is deliberately _not_ the same as `false`.
- **Realistic log density.** Early cards were 8–12-fact schema dumps and were rejected. Final data is mostly 2–6 facts, with one-fact and long rambling logs kept deliberately.
- **No dates, drug names, or doses** anywhere in labels.
- **Held-out structures for gold.** Train/validation use S1–S7; gold uses S8–S10 (subordinate clauses, corrections/contrasts, imperatives) plus empty, off-topic, and adversarial-injection inputs.
- **Two-layer audit on every record:** a deterministic script (fidelity, arithmetic, structure, realism) and an independent LLM auditor, then my manual acceptance per batch (though I barely looked at the AI generated dataset which is a weakness). Files are hashed on freeze.
- **Model selection on validation only.** One checkpoint per epoch, chosen by validation macro field-level F1 — never by training loss, never by gold.

## 🔍 What I Learned

Data quality is always a key issue, but for more nuance:

- **Having AI agents verify each other can still overlook mistakes.** Classic how do I trust the judge problem. For example, several generated cases had sleep_quality as fair, but also described insomnia, which I saw as contradictory but the model didn't. Telling AI agents to create more diverse output isn't a deterministic way of doing so, I did have other analysis measures for similarity, but that's not the only metric to look out for.
- **Coverage is not realism.** My first AI generated dataset had perfect field coverage and read like a database export. Rejecting it and regenerating for density and varied phrasing was the single biggest data-quality improvement.
- **Leakage can hide in labels, not text.** Text-level duplicate checks passed while six validation cards shared `cycle_day` and `flow` with training cards. Those had to be re-selected.
- **The two audit layers catch different things.** The LLM auditor missed a silently omitted symptom; the script caught it. The script rejected correct texts containing typos; the LLM accepted them. Neither is sufficient alone.
- **Validity can increase fabrication.** A grammar forces the model to commit, and a weak model commits to invented content. Parse rate and F1 must be reported together.
- **Conservative generation has a cost.** Training text avoided ambiguous tone, so testing whether the model over-reads mood required deliberate handwritten distractor cases.
- **Read the errors in the log carefully each time** Lot's of time went into a "truncated JSON" bug whose real cause was a library rejecting mixed-type enums (printed several lines above the exception I was focusing on and overlooked due to repeated errors)

## 🚀 Future Work

It was a fun side project that could serve me in other work as well and be extrapolated for other cases, definitely learned from it.
If I want to take use this seriously I should fix the consistency issues in severity, as well as improve data, but honestly 80% isn't bad at all for an app use.
Users can transcribe from speech, pass the text into this model, and have the logs show up on screen fully selected. A user only has to glance quickly and make sure what they intended was understood (e.g mild cramps vs moderate vs severe cramps)

- **Severity-focused data:** more long-form, band-diverse examples (`mild`/`severe` in complex sentences) — the clear next accuracy win.
- **Scale back up** to the validated 400-card superset without any redesign.
- **Deeper error analysis:** per-structure F1 (S8/S9/S10), severity confusion matrix, and the distractor slice (tone vs mood, injection resistance).
- **Demo:** merge the adapter and export to GGUF for a small local demo of log-to-JSON extraction.
- **Second iteration on severity calibration**, keeping gold frozen so results stay comparable across versions.
